* Problem

The Owner could not read the raw JSON an agent receives: the acp package only
keeps traffic buffers when ~acp-logging-enabled~ is on, and it is off by
default — so nothing was readable. And the session id shown in the header
line had to be retyped by hand into ~agent-org-resume-session~ or a shell,
which is how ids get mistyped.

* Requirements

1. ~agent-org-log-traffic~ — a defcustom, default ON, that turns on
   ~acp-logging-enabled~ at client creation, so the traffic buffer exists
   without the user hunting for the acp knob.
2. ~agent-org-show-traffic~ — an interactive command that opens the current
   chat session's ~*acp-(agent)-N traffic*~ buffer; RET on a line
   pretty-prints that message's JSON. Demands a chat and a live client;
   names the switch when there is nothing to show (echo area / user-error
   shaped like the package's other commands).
3. ~agent-org-copy-session-id~ — puts this chat's ACP session id on the
   kill ring; refuses (leaves a stale kill ring untouched) before the
   handshake has produced an id.
4. Tests (appended to ~tests/test-agent-org.el~): four traffic tests
   (demands-a-chat, needs-a-live-client, names-the-switch-when-empty,
   opens-this-chats-log) and two copy-id tests (copies after the handshake;
   refuses before it).
5. Documentation: README.org gains a "Seeing the raw wire" section
   documenting the command (a matching section appeared as the concurrent
   agent's uncommitted docs; the implementation was reconciled to it).
6. Mock support: ~tests/acp-mock.el~ grew the ~acp-traffic-buffer~ surface;
   unused-keyword warnings in the mock (~client~ → ~_client~, ~sync~ →
   ~_sync~ in ~acp-send-notification~) fixed so byte-compile stays clean.
