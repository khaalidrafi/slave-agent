* Problem

In agent-org chat buffers the whole doom-modeline bar went blank. Root cause
chain, established by live probing and source reading:

1. agent-org makes its ~* User~ / ~* Agent~ heading lines ~read-only~
   (buffer protection).
2. Org sets ~add-log-current-defun-function~ buffer-locally to
   ~org-add-log-current-headline~, which ends in ~org-get-heading~ — and
   ~org-get-heading~'s arguments are no-tags/no-todo/no-priority/no-comment,
   NOT no-properties, so it answers with ~buffer-substring~-style propertized
   text: the heading, ~read-only~ and all.
3. ~which-func-format~ / doom-modeline's generated function
   (~doom-modeline-format--main~) applies a face (~add-face-text-property~)
   to a string assembled from arbitrary segments; modifying read-only text
   signals ~text-read-only~ during redisplay and the entire bar goes blank.

Note: an early hypothesis (~which-func-current~ / ~which-function-mode~ as
the carrier) was disproved by a live probe; the mechanism-agnostic statement
("any read-only piece blanks the whole bar") is the one that held.

* Requirements

1. Live relief (applied in the Owner's running Emacs via
   /tmp/ao/ml-fix.el): a named, removable ~:around~ advice on
   ~doom-modeline-format--main~ binding ~inhibit-read-only~, plus removal of
   the session's own diagnostic ~:before~ probes on
   ~add-face-text-property~ / ~message~ (a probe on ~add-face-text-property~
   fires on every redisplay and helped wedge the box — see specs/012).
2. Persisting that advice means editing
   ~~/home-config/dotfiles/.emacs.d/personal/khalid-ui.el~ (≈12 lines,
   docstring naming the mechanism) — the Owner's AGENTS.md forbids editing
   $DOTFILES without explicit permission; the session asked for the word
   ("Say 'edit khalid-ui.el' and I will").
3. The agent-org-side fix (mechanism-agnostic, package-scoped):
   - ~agent-org-buffer--property-free (value)~: a fresh ~copy-sequence~ with
     ~set-text-properties … nil~ — a display string that carries no
     ~read-only~ at all.
   - ~agent-org-buffer--install-plain-defun~: at ~agent-org-mode~ enable,
     capture the buffer-local ~add-log-current-defun-function~ (falling
     back to ~#'org-get-heading~) into
     ~agent-org-buffer--defun-function~ and install a wrapper that returns
     the original's answer property-free (preserving its
     nil-when-not-on-a-heading behaviour).
   - On ~(agent-org-mode -1)~: ~kill-local-variable~ both
     ~header-line-format~ and ~add-log-current-defun-function~.
   - A docstring sentence on the mode explaining the routing.
4. Regression test ~test-agent-org-which-function-answers-property-free~:
   after ~agent-org-buffer-create~ and a prompt at ~* User~:
   - ~(funcall add-log-current-defun-function)~ → ~"User"~ with no
     ~read-only~ text property, and applying a face to it does not error;
   - the heading itself is still ~read-only~ (protection untouched);
   - after ~(agent-org-mode -1)~ the variable is not buffer-local.
