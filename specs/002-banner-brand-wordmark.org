* Problem

The startup banner spelled the product name in six rows of Unicode block
glyphs (~██╗ ██╗…~) in two places — ~hermes_cli/banner.py~
(~HERMES_AGENT_LOGO~) and ~ui-tui/src/banner.ts~ (~LOGO_ART~). A rule over
words cannot see a shape: the generator could not rewrite the drawn name, so
the branded branch would ship a banner still spelling the upstream name
(FORK.org gap 1: "Needs regenerated art (or art derived from ~brand.CLI~)
plus a rule/test that fails if the old art returns").

* Requirements

1. ~hermes_cli/banner.py~: delete the ~HERMES_AGENT_LOGO~ block-art constant
   and render the nameplate through a new function ~_brand_wordmark()~
   spelled from ~brand.PRODUCT~ and ~brand.TAGLINE~ (the wordmark is
   ~brand.TAGLINE~'s first consumer — it was unused before), keeping the
   gold→bronze gradient rich markup, the release-date/version line, and the
   existing ≥95-column display gate (rendered width 50, so it prints on
   normal terminals).
2. ~import brand~ moves to banner.py's top import block (first-party, next to
   ~from hermes_constants import get_hermes_home~).
3. ~hermes_cli/skin_engine.py~: update the comment that referenced
   ~HERMES_AGENT_LOGO~ to name the new function. Skins keep their own
   block-art logos — they spell the *skin's* name (ARES, etc.) plus "AGENT",
   which is brand-safe and must not be touched.
4. ~ui-tui/src/banner.ts~: replace the six-row ~LOGO_ART~ with a ~3~-row
   nameplate built from a quoted literal (~'Hermes Agent'~ on the dev
   branch) that the brand tier's ~rewrite_js~ quoted-region engine CAN
   rewrite on the branded branch; adjust ~LOGO_GRADIENT~ to ~[0, 1, 2]~;
   ~LOGO_WIDTH~ stays computed from the art (only used as a default width).
5. Add a regression test to ~tests/hermes_cli/test_banner.py~
   (~test_default_logo_is_spelled_from_brand_not_drawn_in_glyphs~): strip
   rich markup from ~_brand_wordmark()~ and assert it contains
   ~brand.PRODUCT~ and ~brand.TAGLINE~ and contains no run of full-block
   glyphs (no drawn letters).
6. CI guard (lands with specs/003's workflow rewrite): a ~git grep -l -I -F~
   for the exact deleted row-1 signature
   ~██╗  ██╗███████╗██████╗ ███╗   ███╗███████╗███████╗~ must return nothing —
   it catches the old art returning; the general rule is what ~--lint~ plus
   the unit test enforce.
7. The glyph-run example must NOT appear even in a docstring (the session had
   to strip ~██╗  ██╗~ from ~_brand_wordmark~'s own docstring after the guard
   matched it).

* Acceptance criteria

1. ~rg -n "██╗" hermes_cli/banner.py ui-tui/src/banner.ts~ finds no
   name-drawing art (skin art in ~skin_engine.py~ is allowed).
2. Rendering the Python plate (~_brand_wordmark()~) prints a nameplate
   derived from ~brand.PRODUCT~ / ~brand.TAGLINE~ (transcript: verified, width
   50).
3. ~HERMES_PYTHON=$PWD/.venv/bin/python scripts/run_tests.sh tests/hermes_cli/test_banner.py~ green — transcript records 6 passed
   (5 pre-existing + 1 new).
4. The full row-1 signature grep is empty over the tracked tree.
5. No JS test referenced the logo art (checked in session; none broke).
