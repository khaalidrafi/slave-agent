* Problem

The generator protects ~NousResearch/hermes-agent~ (case-sensitive KEEP_RE),
but measured over the tree it would rewrite *other people's names* on the
branded branch, producing broken instructions and broken model catalog
entries. Task #35 ("Decide the KEEP list: third-party NousResearch repos,
Docker images, model IDs") was created to hold this; it blocks task #28
(produce the branded branch for real), and the session's standing constraint
was that keeping upstream mentions at all "needs your explicit blessing"
(Owner decision, gap 7).

Measured findings (transcript, 2026-10-15):

1. Lowercase ~nousresearch/hermes-agent~ — the real Docker Hub path, ~19+~
   files including ~Dockerfile~, ~docker-compose~, ~scripts/releases/docker.py~,
   docs — gets rewritten to ~nousresearch/slave-agent~, a nonexistent image;
   this breaks docker builds/runs and the release push. KEEP_RE is
   case-sensitive → bug in the protection, same repo, same owner.
2. ~pkg uninstall slave-agent~ (Termux APT) and "remove ~slave-agent~ from
   your flake" (Nix) get rewritten to ~slave-agent~ — defensible only if the
   branded fork actually publishes those channels; today they are upstream's
   real packages.
3. Other NousResearch repos/models found as ~nousresearch/<token>~ hits:
   ~slave-sandbox~ (32 refs), ~NousResearch/slave-example-plugins~,
   ~slave-nvidia~, ~nousresearch/hermes-4-405b~ (a model ID),
   ~NousResearch/Hermes-3-Llama-3.1-70B~, ~NousResearch/atropus~,
   ~NousResearch/api~, ~NousResearch/pokemon-agent~. Rewriting model IDs
   breaks inference endpoints and links.
4. 79 Docker image refs and 663 ~NousResearch/hermes-agent~ mentions are
   deliberately-unchanged upstream facts overall.
5. Existing protected KEEPs that already survive both tiers:
   ~NousResearch/hermes-agent~, ~hermes-agent.nousresearch.com~, ~@hermes.dev~,
   ~hermes-parser~, ~hermes-estree~ (Meta's JS packages).
