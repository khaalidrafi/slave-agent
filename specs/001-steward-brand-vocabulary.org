* Problem

~slave_cli/steward.py~ (steward classification and refusal text for sealed
install trees) contained a hand-typed brand literal: the Guix
update/uninstall refusal told the user to ~guix install slave-agent~ as a raw
string. FORK.org forbids hand-edited brand strings: the generator rewrites
old-vocabulary prose, but a fork-owned *fact* (the name of the package this
fork actually publishes, typed at a shell by a user) must already be true on
the dev branch and must be drift-proof. Upstream package names in the same
file (Termux APT, Nix) belong to someone else's published artifacts and are
functional KEEPS, not prose.

* Requirements

1. ~slave_cli/steward.py~ imports ~brand~ (root module; ~setup.py~ ships
   every root module, so the import also works in an installed wheel) and the
   Guix update + uninstall refusal messages name our package via
   ~brand.SLUG~ (runtime f-string), never a hand-typed literal.
2. The upstream Termux APT and Nix package names (~slave-agent~) stay as
   literal keeps, documented by the comment block at the ~import brand~ site:
   a user who installed through those channels has upstream's artifact, so
   telling them to remove *our* slug would name a package that does not exist
   on their machine.
3. A relationship test appended to
   ~tests/slave_cli/test_steward_detection.py~ (class planned as
   ~TestBrandVocabularyInRefusalText~) asserting only what is durable across
   dev and branded branches:
   - the Guix update and uninstall refusals contain ~brand.SLUG~;
   - the Termux/Nix refusals name upstream's published package, derived as
     ~brand.UPSTREAM.split("/", 1)[1]~ (= ~slave-agent~), and do NOT contain
     ~brand.SLUG~.
4. Task #23 companion fix (same session, same commit lane): ~brand.py~
   ~HOME_ENV~ must agree with what the generator's identity-tier ~SLAVE_~
   arm actually produces (the mechanical swap drops ~_AGENT~), guarded by the
   existing tests in ~tests/scripts/test_rebrand_brand_agreement.py~
   (~test_every_brand_name_is_what_the_generator_produces_for_its_upstream_token~
   and the ~export SLAVE_HOME=$SLAVE_HOME~ untouched-identifier case).
5. Known pre-existing red tests are NOT in scope: 5 cases in
   ~TestUpdateAdmission~ import the deleted ~slave_cli.update_contract~
   (updater-removal tail — see specs/006).
